# 하드웨어 로드맵 (B 트랙): USB 연결형 AI 장치

## 1. 물리적 제약에서 출발하기
토큰 1개를 생성하려면 **활성 가중치 전체를 메모리에서 한 번 읽어야** 합니다. 그래서 생성 속도 상한은 다음과 같습니다.

```
tok/s ≤ 메모리 대역폭 ÷ 토큰당 활성 바이트
```

| 모델 (4-bit 근사) | 전체 가중치 | 토큰당 활성 바이트 | 10 tok/s에 필요한 대역폭 |
|---|---|---|---|
| Llama 3.1 8B | 약 4.9GB | 약 4.9GB | 약 49GB/s |
| Llama 4 Scout 109B (활성 17B) | 약 61~67GB | 약 10.4GB | 약 104GB/s |
| gpt-oss-120b (활성 5.1B) | 약 62GB | 약 2.7GB | 약 27GB/s |

(근사치: bpw 4.9 기준. gpt-oss는 MXFP4 4.25bpw. 실제 값은 GGUF 헤더로 확인합니다.)

- USB 3.2 Gen2(10Gbps)의 이론치는 약 1.25GB/s, USB4·Thunderbolt 4는 약 5GB/s(40Gbps)입니다. **가중치가 링크를 건너는 구조는 어떤 USB로도 실용 속도가 나오지 않습니다.**
- 결론: 장치가 의미를 가지려면 **가중치 전체를 장치 자체 메모리에 상주**시켜야 합니다. 그러면 링크로는 토큰만 오가므로 USB 대역폭은 무관해집니다.

## 2. 그래서 장치는 "가속기"가 아니라 "메모리가 큰 작은 컴퓨터"가 됩니다
| 등급 | 장치 메모리 | 대역폭 목표 | 실행 가능 | 기존 사례 |
|---|---|---|---|---|
| S | 8GB | 30~70GB/s | 1~8B | UGen300, MLD-R1 (USB 가속기) |
| M | 32~48GB | 100~150GB/s | 30B dense, Scout IQ2 | (공백) |
| L | 80~128GB | 200~300GB/s | Scout Q4, gpt-oss-120b | Tiiny Pocket Lab(80GB), DGX Spark(128GB) |

- L 등급은 이미 Tiiny와 DGX Spark가 있고, BOM에서 LPDDR5X 80GB만 $900 이상이라는 보도가 있습니다 🔎. 스타트업이 하드웨어 원가로 경쟁하기는 어렵습니다.
- **기회는 M 등급의 공백 + 호스트 하이브리드**입니다. 호스트 GPU에 attention과 공유 가중치를 두고, 장치 메모리에 라우팅 전문가를 두면, 링크로는 토큰당 활성화 값(수십 KB~수 MB)만 오갑니다.

## 3. 단계별 로드맵
| 단계 | 기간 | 내용 | 검증 지표 |
|---|---|---|---|
| H0 | 해커톤 | USB = 저장소. 연산은 호스트(현재 프로토타입) | 판정 정확도, 실측 tok/s |
| H1 | 1~2개월 | **기성 미니 PC나 SBC를 "장치"로 사용**: USB-C 네트워킹(USB gadget Ethernet 또는 Thunderbolt 네트워킹)으로 호스트와 연결. 장치에서 llama-server를 돌리거나, llama.cpp의 **RPC 백엔드**(`ggml-rpc`, 소스에서 확인)로 호스트와 레이어를 분할 | 링크 지연과 대역폭이 tok/s에 주는 영향 실측 |
| H2 | 3~6개월 | PocketLLM 플래너를 "호스트 + 장치" 2-노드 배치로 확장(MoE 전문가는 장치, attention은 호스트 GPU). 전문가 라우팅 통계로 hot expert를 호스트 VRAM에 캐시(PowerInfer의 hot/cold 아이디어를 MoE에 적용) | 같은 모델에서 호스트 단독 대비 개선 |
| H3 | 6~12개월 | 맞춤 하드웨어 검토: LPDDR5X 대용량 SoC(Arm 또는 RISC-V + NPU) 기반 M 등급 레퍼런스 보드, 발열과 전력(USB-PD 60~100W) 설계 | 원가 대비 GB·(GB/s) |

## 4. 위험과 확인 과제
- **전력**: USB-PD 100W 이하로 L 등급 SoC를 지속 구동할 수 있는지(Tiiny는 65W라는 주장 🔎)
- **드라이버와 OS**: 장치를 "네트워크 장치"로 노출하면 커스텀 드라이버가 필요 없습니다(H1 방식의 장점).
- **사업**: 하드웨어 마진 vs 소프트웨어 구독. 단기 수익은 "모든 로컬 AI 장치에서 동작하는 판정·튜닝·배포 계층"(B2B: 사내 오프라인 AI 키트)이 더 현실적입니다.
- **법과 라이선스**: Llama Community License(MAU 조항, 표기 의무), Muse Glimmer(Apache 2.0)는 재배포에 유리합니다. 모델을 미리 탑재해 판매하려면 각 라이선스의 재배포 조항을 확인해야 합니다.
